# 富文本与源码模式

<span class="version-badge">适用于 HorseMD v0.13.51</span>

点击状态栏中的“富文本/源码”，或按 `Ctrl/Cmd+/` 切换模式。

![HorseMD 源码模式](/images/v0.12.10/source-mode.png)
<span class="image-caption">源码模式保留 Markdown 标记，适合检查语法、批量编辑或处理复杂结构。</span>

## 两种切换行为

HorseMD 会根据你是否正在编辑决定定位方式：

1. 光标在可视区域内：切换后跟随对应光标，保证光标仍然可见。
2. 没有可见光标，只是在滚动阅读：切换后保持当前阅读视口，不会突然跳到旧光标。

表格单元格、行内代码、行内公式、代码块和重复文字使用结构化位置映射，不依赖简单关键词搜索。富文本编辑器在源码模式下保持挂载，因此切回时不会重新解析整篇文档或重新加载远程图片。超长文档在纯阅读切换时只恢复当前视口，不会为了不可见的旧光标重新扫描整篇文档；在公式附近编辑时，光标也会跟随同一段文字。

## 源码 + 预览（桌面）

在富文本编辑区右键，选择“**源码 + 预览**”。同一份文件会在左侧显示 Markdown 源码、右侧显示富文本效果：

- 在左侧写 Markdown，短暂停顿后右侧会更新预览；
- 右侧只用于预览、滚动、选中和复制；编辑、格式化、评阅与右键操作都在左侧源码完成；
- 拖动中间分隔线可调整两边宽度；
- 两侧滚动会按当前段落联动。图片、表格和代码块的高度不同，因此目标是定位到同一段内容，而不是让两个滚动条机械地处于相同比例；两侧到底时的尾部阅读留白保持一致；
- 右侧预览不会显示编辑右键菜单；右上角的“关闭预览”会直接回到普通富文本视图。状态栏的“富文本/源码”仍可用于进入单一源码视图；
- 源码中的加粗光标完整显示在字符边界前。无论是首行还是中间非空行，都可以直接点击首个字符的起始区域（例如 `## 页面对应关系` 的第一个 `#`）并在该字符前输入。

该模式只在桌面 Markdown 文档中提供。纯文本、未加载富文本的超大文档，以及已经开启“两份文件分屏”时不会显示。

## 源码编辑与保存状态

只切换模式不会把标签标记为“已修改”。在源码文本框真正输入、删除或粘贴后，新内容才会同步回富文本并进入未保存状态。Windows 文档常用的 CRLF、UTF-8 BOM 和文件中已有的混合换行也会保留；在源码中只改一处，不会顺带统一整篇换行格式。

在富文本中只修改局部文字时，HorseMD 会保留未修改区域原本的 Markdown 写法，例如空行、列表标记、必要的转义和图片替代文字。`![图片说明](图片地址)` 在富文本编辑、保存或切换源码后仍会保留“图片说明”，不会被尺寸值替换。将 Markdown 源码直接粘贴到富文本中时，即使复制来源同时带有网页格式，也会优先保留原始 Markdown；从微信公众号等网页粘贴图文时则保留网页的标题、格式和图片，单独图片粘贴后也可以直接切换源码、保存并重新打开。进行标题层级、列表类型等跨区块结构调整时，受影响的区块可能会按 Markdown 规范重新生成；需要逐字符控制复杂语法时，请使用源码模式。

连续有序列表统一使用标准的 `1.` 写法。若富文本操作暂时产生了标准 Markdown 无法单独表达的相邻有序列表，HorseMD 会在富文本中合并为同一连续列表，不会在源码中插入 `1)` 或隐藏注释；在一个有后续条目的列表中从空项退出、再按 `Enter` 也会按这一规则收敛。相同操作发生在嵌套有序列表时，会写成标准的空父项与缩进子列表，因此后续编号和正文可以正常保存。作者原本写成 `1)` 的列表，以及源码中原有的独立 `<br />`，仍会保留原样。

新建空文件可以从标题开始，也可以直接点击正文起笔。直接写正文时，编辑器初始界面中未使用的空标题不会写入源码，也不会导致保存暂停；已经存在于作者 Markdown 中的空标题不会因此被删除。

从列表末尾开始写普通正文时，先在最后一项末尾按 `Enter` 产生空列表项，再按一次 `Backspace` 退出列表，然后直接输入正文。此时如果不输入文字而再次按 `Backspace`，空段落会重新并回上一列表项；随后再按 `Enter` 出现新的列表序号是正常结果。要重新退出，在这个新的空列表项再按一次 `Backspace` 即可。

如果在列表项正文开头输入看起来像下一层列表的文字，例如 `2. 测试` 或 `- 测试`，源码可能显示为 `2\. 测试` 或 `\- 测试`。这些是 Markdown 为保持“普通正文”结构所需的转义，不会出现在富文本中；去掉后，重新打开文件可能会变成嵌套列表。

段落、引用和列表项末尾新输入的普通 ASCII 空格会按字面空格保存，不再改写成 `&#x20;`。行首若需要保留空格，源码使用标准 `&nbsp;` 表示第一个空格，余下空格保持字面值；这是通用 Markdown/HTML 能识别的写法，不会写入 HorseMD 专用零宽字符，也避免被解析为缩进代码块。

空任务项会保存为普通列表文本 `* [ ]` 或 `* [x]`（并保留原有的列表 marker）。GFM 没有“空复选框”的标准源码：裸写法会被所有 GFM 工具理解为普通文字列表。因此 HorseMD 不写 `&nbsp;`、HTML 数字实体或私有标记来伪造 checkbox；重新打开后它同样显示为普通列表文字。

如果空段落的第一个内容，或标题文本的行首/行尾，是 Tab，源码会使用标准 `&#x9;` 表示这个真实制表符。直接写原始边界 Tab 会被通用 Markdown 当作结构或格式空白；数值字符引用可由其他 Markdown/HTML 工具正常解码，不依赖 HorseMD 专用标记。标题边界的普通空格仍遵循同一源码规则：行首为 `&nbsp;`，行尾保持字面空格。

上面两段描述的是默认的富文本模式。注意默认模式里在普通段落中按 `Tab` 键插入的是四个普通空格而不是制表符（列表中 `Tab` 用于缩进嵌套），所以 `&#x9;` 针对的是文档中已经存在的真实 Tab（粘贴进来或源码里原有的）。在源码权威内核（**现已是默认编辑架构**）下，这类边界空白不再写实体，而是写真实的 U+00A0 空白字符——两种写法解码为同一字符，属于有意的分歧，详见下文内核一节。

在两个已有内容块之间按 `Enter` 新建空段落时，HorseMD 会把它保存为额外的标准 Markdown 空白行，不会写入 `<br />`、注释或私有字符。若直接把这行输入为列表，列表会取代这个空段槽位，不会在列表前多留一段空白。连续空白行保留在源码和磁盘中；按通用 Markdown 规则重新进入富文本时，它们可能显示为同一个段落间隔。

切换源码、保存和导出前，HorseMD 会用与富文本编辑器相同的 Markdown parser 验证待提交源码。合法的非满行表格会先形成稳定的 editor-only 结构，但源码仍保留作者原来的短行写法；表格里的转义竖线和手动 `<br>` 也不会被当作普通分隔符或内部占位，包括单独位于 cell 中或位于 cell 文字末尾的换行。每次富文本编辑、保存和切换都绑定到同一个编辑 revision，较晚到达的旧回调不能覆盖新内容。代码块语言名称和围栏中“像表格”的文字不会改变这些同步规则。

若严格验证仍无法提交，应用会先询问是否用当前富文本重建源码；重建也失败或被取消时，可以把当前画面另存为 `.horsemd-recovered.md`。恢复副本只写用户选择的新路径，原文件不变；它用于救回可见内容，可能规范化空行、marker 和转义，不能替代作者原始源码。表格恢复会按保存时仍可证明的 cell 坐标移除编辑器内部空占位，不会全局删除用户手写的 `<br />`；坐标身份仍可证明的恢复表格可在冷重开后继续编辑和保存，无法证明时仍会安全暂停并保留两侧内容。

源码模式支持 `Ctrl/Cmd+F` 查找，当前结果会高亮并滚动到可见区域。从富文本带着查找栏切换过来时，HorseMD 会为新视图重建匹配结果。

## 源码权威内核（默认）

> **2026-08-22 更正**：源码权威内核**现在是默认的编辑架构**——新打开的文档标签页直接以内核模式工作，编辑操作作用于 Markdown 源码本身，而不是先改富文本再回写源码。状态栏“富文本/源码”按钮旁的小 ▾ 菜单仍在：现在它的作用是把**当前标签页**切回旧的普通模式（例外选择会随会话记住，重启后保持）。本指南旧版把内核描述为“实验开关、默认关闭、重启失效”——三条都已过时。

### 当前支持

- 段落与标题文字编辑（含段首按 `Enter` 在光标前插入空行、块尾连续按 `Enter` 每次新增一行空白，语义已修正）。
- 列表族（有序/无序/任务列表）的输入与结构操作、任务复选框勾选。
- 代码块正文编辑（文字输入、换行、删除，含引用/列表嵌套的代码块；Windows 风格 `\r\n` 与单独 `\r` 换行的围栏同样可编辑，行尾拼写按原样保留）、代码块语言切换、`Mod-Enter` 退出代码块。
- **加粗/斜体/删除线/行内代码**的施加与撤销（工具栏、右键菜单、快捷键三条路径一致；含行内代码的文档挂载映射正常，不再降级），以及加粗等格式文字之后段落内其余位置的普通打字。
- **引用/取消引用**（右键块菜单，段落、标题、列表整块与松散列表均可用，源码内核开关开/关行为一致）。
- **数学公式**：含行内 `$x^2$` 与多行 `$$ … $$` 块级公式的文档可以正常挂载，不再整篇退回普通模式；块级公式的内容也可以直接打字编辑（像普通代码块一样），在空的 `$$` 块里输入第一个字符同样安全。仍被拒绝的只有 `$$` 块内的 `Mod-Enter` 退出与语言切换，见下方“被拒绝的操作”。
- **行内 HTML 片段**：含 `<span>…</span>` 等片段的文档正常挂载，不再整篇退回普通模式；在片段外按 `Enter`/`Backspace` 等结构操作正常。同一段落里**片段以外的位置现在可以正常打字**（含紧贴片段左右两侧），整段片段也可以整体选中删除或替换；只有把片段删掉一半这种拆开语法的操作会被拒绝——同行内公式、行内图片。
- **黄色高亮**：`==黄色高亮==` 所在段落可以正常编辑；工具栏的黄色高亮按钮可以施加与撤销。
- **表格单元格文字**：可以直接在单元格里输入与删除；`Tab`/`Shift-Tab` 仍是跨单元格移动光标，不会写入任何字节；分隔行与对齐写法逐字节不变。
- **表格结构操作**（2026-08-22 起）：表格悬浮手柄上的**加行/加列按钮、删行/删列按钮、对齐三键**都直接改写源码的 `|` 行——加的行/列用标准空单元格写法、删除逐行精确移除对应段、对齐改写分隔行的 `:---`/`:---:`/`---:`。删到只剩一行/一列、以及无法安全证明的表格写法（行尾缺竖线、列数参差等）会给出具名提示而不生效；行/列的**拖拽换位**暂不支持。
- **块尾与标题边界的空白**：在段落、标题或表格单元格**末尾**输入的空格/Tab，以及标题文字**行首**的空格/Tab，都会真实写进源码。这类位置的字面 ASCII 空白会被 CommonMark 剥掉，所以内核把它写成真实的不换行空格字符（U+00A0，空格写 1 个、Tab 写 2 个）——源码里看到的就是空白本身，不是 `&nbsp;`/`&#x9;` 实体。粘贴或输入法上屏的文字若以空格/Tab 结尾并落在块尾，结尾的空白也按同一规则改写。之后继续输入文字（含输入法整词上屏）时，该 U+00A0 会在同一次编辑里自愈回普通 ASCII 空格；删除让某个空格重新落到块尾时也会同样改写（一次只认领一个空格；会让 Tab 或连续空白落到块尾、无法无歧义改写的删除会被直接拒绝，而不是乱猜）。只有保存时真正停在块尾的那个空格保持 U+00A0，因此它可见且可保留。这与上文「源码编辑与保存状态」里普通模式的实体写法是有意的分歧。
- **图片地址与图注**：源码里已经写了空的 `![]()` 时，可以在图片输入框里填写地址；**未缩放图片的图注（caption）可以直接在图注输入框里编辑**，写进 Markdown 的 title 槽（`![alt](src "图注")`——与普通模式同一套字节方案）。三种情况会给出具名提示而不生效：已拖拽缩放的图片改图注（缩放方案占用了 alt/title 槽）、在有 alt 的图片上清空图注（Markdown 无法表达“有 alt 但无图注”）、以及拖拽缩放本身（内核不落盘缩放比例）。图片的 alt 仍无界面入口，请在源码模式编辑。
- **标题降级**：光标在标题第一个字符处按 `Backspace`/`Delete` 会真正降级标题（H2→H1、H1→正文；空的一级标题会被整块删掉）。去掉 `#` 后会变成别的结构（如 `# 1. 甲`）或嵌套在引用/列表里的标题会给出具名提示而不生效。
- **评阅（CriticMarkup）**：选中文字后加“新增/删除/高亮+批注”标记、评阅卡片的完成/删除/编辑、以及“全部接受/拒绝”都直接写源码。替换建议 `{~~旧~>新~~}` 的插入会给出具名提示（见上文只读小节），请用“新增+删除”代替。
- **链接**：选中文字 → 工具栏链接按钮 → 在浮层里输入网址 → 确认，以及修改已有链接的网址、移除链接，全部直接写源码。
- 输入法（IME）合成、撤销/重做（含代码块内的撤销/重做）、保存与冷重开。
- **单个区块降级**：某个区块无法安全映射时，现在只把**那一个区块**变成只读并单独提示，文档其余部分照常编辑，不再整篇退回普通模式。

### 暂不支持

限制分三类，**影响范围完全不同**，请对照区分。

#### 一、整篇文档用不了内核（该标签页自动退回普通模式）

以下写法会让内核拒绝接管这篇文档；此时该标签页的行为与没打开开关时**完全一样**——照常编辑、照常保存，只是这次开关没有生效。这份清单不是穷举——内核要求文档能被完整、无歧义地重新解析，任何让这个证明失败的结构差异都会触发同样的退回，下面三种只是已知会稳定复现的具体形状：

> **2026-08-22 更正**：此前列在这里的三种形状（独占一行的 `$$公式$$`、列表项里的块级公式/代码围栏、相邻的根级 `<div>` 块）**都不再让整篇文档退回普通模式**。列表项里的代码围栏可以正常挂载；独行 `$$公式$$` 与合并显示的相邻 `<div>` 现在只是**那一处只读**（见下一小节），文档其余部分照常用内核编辑。

> **2026-08-21 更正**：本指南此前在这里写着「超过约 12 万字符的文档……同样退回普通模式」。**该限制已经取消**——超大文档现在可以正常使用源码内核，见下面这段。

**超过约 12 万字符的文档**会先被分块加载，而分块加载得到的结构与内核对整篇源码的一次性解析确实可能不一致（例如空行分隔的多个列表，整篇解析下是一个连续列表，分块加载下是两个）。现在 HorseMD 会在**加载结束的那一刻**把编辑器里的文档重新对齐成整篇解析的结果，只改动真正不一致的那几处，再让内核接管；你会看到的只是打开大文档时最后多花零点几秒（200 KB 的文档实测约 0.4–0.7 秒，一次性），代码块、图片这些内容不会重新加载。之后就和普通大小的文档一样使用。

两点仍然要注意：文档**还在加载**时点内核开关会被拒绝并提示稍后再试（加载中的文档只有一半在编辑器里，此时切换会丢内容）；如果重新对齐之后内核仍然无法接管这篇文档，提示会明确说明是哪一种情况，标签页照常退回普通模式。

#### 二、只有某一处变成只读（文档其余部分照常编辑）

这类写法不影响整篇文档，只是**那一处**不能改，并会单独给出“此段落在内核模式下暂为只读”的提示：

- 红色/蓝色高亮所在的那一段（它们以 `<mark class="hm-hl-…">` 形式保存；黄色高亮不受影响，可以正常编辑）；
- 独占一行写成 `$$公式$$` 的块级公式（显示正常，那一块只读；改写成 `$$`、公式、`$$` 三行即可编辑）；
- 两个只隔一个空行、被合并显示的相邻根级 `<div>` 块（合并显示的那一块只读）；
- 含替换建议标记 `{~~旧~>新~~}` 的段落（`~~` 对源码解析器是删除线语法，无法安全证明；用“新增+删除”两个标记代替即可）；
- ~~含 `<br>` 换行的表格单元格~~ **2026-08-29 更正**：含 `<br>` 换行的单元格现在可以正常编辑，且在单元格内按 Enter / Shift+Enter / Cmd+Enter 会插入 `<br>` 换行；仅含转义 `\|` 竖线的单元格仍只读（**只有该单元格**只读，同表其它单元格照常输入）；
- 列数参差或超出映射能力的表格——**整张表**只读，但文档里表格以外的部分照常编辑。

含**硬换行**（行尾两个空格或反斜杠换行）的段落现在可以正常打字，不再整段拒绝输入。行内公式、行内图片、行内 HTML 片段所在的段落同样可以正常打字（含紧贴片段左右两侧），选中整个公式/图片/片段按 `Backspace` 删除也可以（连同前后文字一起删同样可以）。只有两种情况仍被拒绝：把某个公式/图片/片段拆开一半，或删除**带链接的图片**（它的 `[` 与 `](链接)` 不属于图片本身，单删图片会留下孤立的链接符号）。这两种拒绝显示的是更笼统的“暂不支持此操作”提示，不是上面三条的“此段落…只读”提示——操作不生效，但段落本身仍可继续编辑。

#### 三、被拒绝的操作（提示后不生效，不会损坏文档）

- 块级公式 `$$..$$` 内的 `Mod-Enter` 退出与语言切换、块级 HTML 的编辑。块级公式和 mermaid/LaTeX 预览块本身的文字**现在可以正常编辑**（就像普通代码块一样，切到“编辑”即可打字），不再属于本条。
- ~~表格的行列增删与对齐切换~~ **2026-08-22 更正**：表格悬浮手柄的加行/加列、删行/删列与对齐三键都已支持（见上文「表格结构操作」条目）；仍拒绝的只有行/列**拖拽换位**、删到只剩一行/一列、以及无法安全证明的表格写法。
- 图片的图注（caption）与拖拽缩放比例——它们属于富文本显示状态，不写进源码。
- 评阅（CriticMarkup）标记。
- 给一个裸网址加高亮。
- 直接在加粗/斜体等已有标记文字内部继续输入（“续加粗”手势）。
- 斜杠菜单的「分割线」（`/divider`）与「图片」（`/image`）在**插入后光标无处安放**时拒绝：插入位置既不在文档末尾，下方紧跟的又不是文字段落或标题（而是列表、表格、代码块、引用、另一个分割线/图片等）。提示原文：「未插入：插入后光标将无处安放（下方不是文字段落或标题）。请在文档末尾插入，或先在下方添加一行文字。」
- 斜杠菜单的「正文」（`/text`）在**清空该块会让上下两块合并**时拒绝——典型形状是它夹在两个**同种记号**的列表之间（都用 `-`，或都用 `1.`；空行并不会结束 CommonMark 列表，删掉中间这块两个列表就并成一个，而“并成一个列表以后两项之间的空行”在源码里根本没有位置可以放光标），以及删掉它以后在原位打字会被上一段“吃掉”（上一块与它之间没有空行）。两个列表若用的是**不同记号**（`-` 与 `*`、`-` 与 `1.`、`1.` 与 `1)`），CommonMark 本来就不会把它们合并，这时 `/text` 正常可用。提示原文：「清空此块会让上下相邻的块合并（此处的空行在 Markdown 里没有对应写法）。请直接删除斜杠命令文字，手动编辑该块。」文档中段的一般情况（两段之间、标题下方、列表与段落之间、围栏/表格/公式/分割线前后、以及文档第一块）现在都正常可用。
- 在紧邻一个**缩进**列表（例如上一级列表下方缩进两格的子列表）的段落里用 `/task`。原因：新写入的任务项会把那个缩进列表**吞成自己的子列表**，这不是这次插入写下的结构。提示是通用的「源码权威内核实验阶段暂未支持此操作」；把光标放到该缩进列表最后一项末尾按 `Enter` 续一项即可。
  > **2026-08-21 更正**：本指南此前把「在紧邻既有列表（正上方或正下方）的段落里用 `/task`」整条列为被拒绝的操作。那条限制已经取消——普通（不缩进）的相邻列表现在可以正常合并，见下文 `/task` 条目。
- ~~在**标题的第一个字符处**按 `Delete` 或 `Backspace`~~ **2026-08-22 更正：「标题降级」手势现在直接生效**。这两个键在该位置不是「删除字符」，而是标题降级手势（H2→H1、H1→正文），内核现在会真正改写标记字节：二级及以下标题少一个 `#`；一级标题去掉 `# ` 前缀变成正文段落（光标落在段首，可直接输入）；**空的一级标题会被整块删掉**（光标留在原地的空行上，与 `/text` 同一套机制——此前它完全删不掉，正是这次更正的起因）。仍被拒绝的只剩两类：去掉 `#` 后这一行会**变成别的结构**（例如 `# 1. 甲` 会变成有序列表、`# # 甲` 仍是标题、`# 甲` 紧贴下一行会与它并成一段），以及**嵌套**在引用/列表里的标题。提示原文：「在标题的第一个字符上按 Delete/Backspace 是「标题降级」手势（H2→H1、H1→正文）。这个标题暂时没法安全降级：去掉 # 后这一行会变成别的结构（如列表、引用、另一个标题），或者标题不在文档顶层。想删掉光标后面那个字符：先按 →（右方向键）再按 Backspace；也可以切到源码模式直接增删行首的 #。」
- ~~在刚用 `/task` 插入、还没输入正文的任务项里按 `Backspace`~~ **2026-08-22 更正：这条已取消**。现在按 `Backspace` 会直接**删掉这个空任务项**（与普通空列表项一致：顶层项退出列表，嵌套项先升一级）——这正是想剔除该项/该列表时的直觉手势。此前它被「任务项不能删成空」拦下，是把「删掉占位字符会留下不可表示的字节」误当成了「这个按键必须拒绝」。那条提示仍然存在，但只出现在**非按键**的删除路径上（例如恰好只选中占位字符做剪切）：空任务项在源码里依旧不可表示，直接删占位字符仍会被阻止。
- 右键列表/块类型转换。
- 在少数 `\r\n`/`\r` 换行代码块里按 `Enter` 换行——只有一行（或空）内容的代码块，以及块内换行风格不统一、且第一行用 LF 结尾的代码块（这两种情况下块内的普通文字输入和删除都不受影响，只是不能在块内换行）。

以下操作现在**可以**通过斜杠菜单完成（此前不行）：标题层级 `/h1`–`/h6`、无序/有序列表 `/ul` `/ol`、引用 `/quote`、新建表格 `/table`、新建代码块及语言变体 `/code` `/js` `/python` `/mermaid` 等、新建块级公式 `/math`、任务列表 `/task`、分割线 `/divider`、图片 `/image`、纯正文 `/text`——菜单上的每一项都有内核路由，`/divider`、`/image` 与 `/text` 的位置限制见上文“被拒绝的操作”。其中：

- **`/quote`** 插入一个空白引用块（源码写入 `>`），光标落在块内可直接输入正文。本指南旧版曾把它列进“被拒绝的操作”并称“不存在能用的场景”——那已经过时：现在每次调用都正常生效。把已有段落变成引用、或取消引用，右键菜单的“引用/取消引用”仍然可用，两种模式行为一致。
- **`/task`** 立即创建一个真实的未勾选任务项：源码写入 `- [ ] ` 加一个占位空白字符（U+00A0，这是 GFM 里“还没有正文的任务项”唯一能被解析成真任务的写法——纯 ASCII 的 `- [ ] ` 只是普通列表文字）。输入正文的第一个字符时，占位符在**同一笔编辑**里被删除、正文写入原位，源码里只留下你输入的文字；作者文件里原有的 U+00A0 永远不会被这样替换。与普通模式的一个刻意差别：如果在输入正文**之前**就保存，磁盘上保存的是一个真实的空白任务项，冷重开后复选框仍在（普通模式会在保存边界把空任务项降级为普通列表文字，见上文「源码编辑与保存状态」）。这样保存再重开后，占位符已成为文件自己的字节，继续输入会接在它后面而不再替换它。紧邻既有列表（正上方、正下方或夹在两个列表之间）时，新任务项会按 CommonMark 的规则**并入**那个列表成为其中一项——这正是你想要的结果，2026-08-21 起支持（此前这一位置整条被拒绝）。合并只发生在记号相同的列表上（都用 `-`）；`*` 或 `1.` 开头的相邻列表本来就不会合并，任务项会自成一个新列表。并入时若原列表是“紧凑”的，它会按 CommonMark 变成“松散”列表——在 HorseMD 里看不出差别，导出到别的 Markdown 渲染器时每一项会多一层段落间距。在任务项末尾按回车**续出的下一个任务项**用的是同一套占位机制：复选框立即可用、输入第一个字符时占位符同样被替换（在已勾选项上续出的新项恒为未勾选）；在刚续出、还没输入正文的任务项上再按一次回车会退出列表，按 `Backspace` 则直接删掉这个空项（顶层项退出列表、嵌套项先升一级——都与普通列表的空项行为一致，2026-08-22 起）。
- **`/divider`** 写入标准的 `---`；唯一的例外是它会成为文档第一块、且后文恰好还有一行 `---` 时（两者会被整体解析成 frontmatter），改写为等价的 `***`。
- **`/image`** 写入 `![]()`，显示为空图片卡片；直接用卡片上的“上传文件/粘贴链接”填写图片地址即可。
- **`/text`** 不写入任何字节：完全空的顶层段落在 Markdown 里没有对应源码，它只删除该块自己的字节（在文档末尾还会一并删掉其后多余的空白字节），并把光标放进原地留下的空行——一个只存在于视图里的空段落，你输入的第一个字符会在原位变成真正的段落。文档中段与文档末尾都可用（文档中段自 2026-08-21 起支持，此前只能用于最后一块）。

另外，文档以分割线或图片**结尾**时，点选中该分割线/图片后直接打字，现在表示“在它下方输入正文”——分割线/图片本身的字节不动（想替换它，请先删除再输入）。位于文档中间、被选中的分割线/图片直接打字仍会被拒绝。

这些操作在关闭该开关时和平时完全一样。

这个开关只属于当前标签页的这次会话，不写入设置或工作区状态；关闭标签页、重开应用后需要重新打开。

## 行内代码的键盘移动

光标位于行内代码（如 `` `示例` ``）首尾时，按 `←` 或 `→` 可以回到相邻正文，继续按方向键会正常穿过前后的文字。不会为了“退出代码”跳过字符、插入隐藏字符或改变原 Markdown。

::: tip 大文档
超大文档可能默认使用快速源码模式。确认设备性能足够后，可以选择进入富文本；图片很多的文档首次渲染需要更多时间。
:::
